# 2026-10-04：远程项目首启引导

2.2.0 的新用户直接进入连接设置，聊天侧栏被隐藏，而远程项目入口仅在该侧栏。第一步继续要求本机文件夹，远程项目存在时也仍显示“尚无”。这是引导缺口，不是安装包缺少远程实现。

第一步现在明确选择 Linux 开发机或本机文件夹。两个远程入口共用现有对话框和项目提交逻辑，操作期间同时禁用，取消或失败不增加完成度。原有 `hasRemoteProjects` 投影决定第一步状态，不增加配置开关或本机目录权限。

远程项目需要 Plugins，因此第 5 步提供插件页面入口，并等待该连接的请求证明。本机项目仍可不配置 Plugins。版本同步到 2.2.1，桥协议保持 14。

验证：

- 相关状态、对话框和本地化测试 108 项通过，TypeScript 与生产构建通过。
- 完整 `npm run verify` 通过：主批次 6882 项、串行收尾 6 项通过，154 项按平台或可选集成条件跳过。隐私、依赖通知与原生源码清单检查通过。
- 两项远程 Electron 检查通过。新增检查加载完整生产页面与默认配置，覆盖中英文首启、1100/800 像素窗口、取消、目录验证失败后重试、成功后留在设置页、本机选择器调用计数、Plugins 导航及聊天侧栏入口。
- Linux/Xvfb 全量界面检查为 34/40；剩余 6 项与 2.2.0 开发时已在原始基线复现的失败相同：聊天滚动、连接弹层图形、消息反馈、宠物透明层、缺少 Chromium、终端尺寸。本次新增首启检查和原有侧栏设置检查均通过；发布继续由原生 macOS CI 验证。
- 首启路径验证使用隔离的后端 fixture，不访问真实凭据、开发机或私人 ChatGPT。未把测试结果表述为用户 Mac 上的端到端验证。
