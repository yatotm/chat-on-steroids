# 2026-10-06：插件状态与本地、远程边界

用户反馈远程主机操作过于占空间，以及 Core 工作正常时插件页仍提示首次设置、旧桥接连接失败。

## 根因与修改

- 远程主机的刷新、添加项目、重连、断开、设置改为单行图标，保留悬停说明和屏幕阅读器名称。
- Core 是项目文件与命令的入口；Plugins 是可选第三方集成。原插件页自己判断连接器配置与使用证据，且无条件催促设置/刷新。现在与设置页共用 `connector-setup.ts`，不向纯 Core 用户报告可选功能未启用为故障。
- 原卡片把缓存清单中的启用位显示成可用数量；连接已经失败仍能出现“32 个工具已启用”。现在分别显示当前可用及已发现数量，保留真实故障。
- 停用旧连接时还暴露了 PluginManager 的过期错误：状态已经 disabled，但 error 字段仍带着前一次 fetch failed。错误在尝试结束、停用及恢复时由运行时所有者处理，界面不自行掩盖错误。
- 插件启动与展示共同使用按安装源派生的运行位置。本机插件和 HTTP 服务不会自动继承当前项目路径；模型端说明也明确该边界。没有引入另一个全局 local/remote 开关或臆测路径转换。

按用户之前明确要求 CoS 与 CodexPro 分开，在确认无项目引用旧插件条目后，仅停用 CoS 中旧桥接条目，保留安装记录和独立服务。没有自动按名称迁移/删除第三方插件的规则。
